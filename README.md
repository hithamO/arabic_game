# 🏰 مملكة الجُمل — لعبة صفية للقواعد (الدرس الحالي: الجملة والتركيب)

لعبة صفّية جماعية لطلاب الصف السادس، والدرس الحالي فيها «الجملة والتركيب». يدخل الطلاب من أجهزة iPad عبر رمز QR، يختار كل طالب شخصيته واسمه، ثم يخوض الجميع مغامرة من 5 مراحل في وقت واحد، ويتابع المعلم التقدم والترتيب مباشرة من لوحة خاصة.

- **صفحة الطالب:** `https://USERNAME.github.io/arabic-game/`
- **صفحة المعلم:** `https://USERNAME.github.io/arabic-game/teacher.html`

(استبدل `USERNAME` باسم حسابك في GitHub.)

---

## 🧪 جرّب اللعبة الآن بدون أي إعداد (وضع التجربة)

قبل إعداد Firebase يمكنك تجربة كل شيء على جهاز واحد:

1. افتح `teacher.html?demo=1` ← اضغط «إنشاء الغرفة».
2. اضغط «فتح تبويب طالب ↗» عدة مرات (كل تبويب = طالب).
3. أدخل الطلاب، ثم ارجع لتبويب المعلم واضغط «ابدأ اللعبة».

أو افتح `index.html?demo=1` لتجربة سريعة لطالب واحد (تبدأ وتنتهي تلقائياً).

> ⚠️ وضع التجربة يعمل على **جهاز واحد فقط**. للعب في الصف مع أجهزة الطلاب يجب إكمال الخطوات التالية.

## الخطوة 1: رفع المشروع إلى GitHub

1. سجّل الدخول إلى [github.com](https://github.com) (أو أنشئ حساباً مجانياً).
2. اضغط **+** أعلى الصفحة ← **New repository**.
3. في **Repository name** اكتب: `arabic-game`
4. اختر **Public** ثم اضغط **Create repository**.
5. في الصفحة التالية اضغط الرابط **uploading an existing file**.
6. فك ضغط ملف المشروع على جهازك، ثم **اسحب كل محتويات المجلد** (الملفات والمجلدات `css` و`js`) إلى الصفحة.
   - تأكد أن `index.html` في المستوى الأول مباشرة، وليس داخل مجلد فرعي.
   - ملف `.nojekyll` مخفي في بعض الأجهزة؛ إن لم يُرفع أنشئه يدوياً: **Add file ← Create new file**، الاسم `.nojekyll`، اتركه فارغاً واحفظ.
7. اضغط **Commit changes**.

## الخطوة 2: تفعيل GitHub Pages

1. داخل المستودع: **Settings ← Pages**.
2. في **Source** اختر **Deploy from a branch**.
3. في **Branch** اختر `main` والمجلد `/ (root)` ثم **Save**.
4. انتظر دقيقة أو دقيقتين، سيظهر الرابط: `https://USERNAME.github.io/arabic-game/`

## الخطوة 3: إنشاء مشروع Firebase

1. ادخل [console.firebase.google.com](https://console.firebase.google.com) بحساب Google.
2. **Create a project** ← اكتب اسماً مثل `arabic-game` ← يمكنك إيقاف Google Analytics ← **Create project**.

## الخطوة 4: تفعيل تسجيل الدخول

1. من القائمة الجانبية: **Build ← Authentication ← Get started**.
2. في تبويب **Sign-in method** فعّل:
   - **Anonymous** ← Enable ← Save (للطلاب — بدون حسابات)
   - **Email/Password** ← Enable ← Save (للمعلم)
3. في تبويب **Users** اضغط **Add user** وأدخل بريدك وكلمة مرور قوية. هذا حساب المعلم.
4. انسخ **User UID** الظاهر بجانب الحساب (نص طويل مثل `aB3dE...`). ستحتاجه في الخطوة 6.
5. في تبويب **Settings ← Authorized domains** اضغط **Add domain** وأضف: `USERNAME.github.io`

## الخطوة 5: إنشاء قاعدة البيانات ولصق القواعد

1. **Build ← Realtime Database ← Create Database**.
2. اختر موقعاً (مثلاً `europe-west1` الأقرب للمنطقة) ← **Start in locked mode** ← **Enable**.
3. افتح تبويب **Rules**، احذف كل ما فيه، والصق محتوى الملف `database.rules.json` بالكامل، ثم **Publish**.

## الخطوة 6: إضافة حسابك كمعلم

القواعد تسمح فقط للحسابات المضافة إلى قائمة المعلمين بإنشاء الغرف والتحكم بها.

1. في **Realtime Database** افتح تبويب **Data**.
2. مرّر الفأرة على السطر الأول (رابط القاعدة) واضغط **+**.
3. في **Key** اكتب: `teachers` — ثم اضغط **+** بجانبه لإضافة عنصر داخله.
4. في **Key** الداخلي الصق **UID** الذي نسخته، وفي **Value** اكتب: `true` ← **Add**.

الشكل النهائي:

```
teachers
   └── aB3dE...xyz : true
```

> 💡 إن نسيت الـ UID: سجّل الدخول في `teacher.html` وستعرض لك الصفحة الرمز مع زر «نسخ».
> لإضافة معلم آخر: أنشئ له حساباً في Authentication ثم أضف الـ UID الخاص به بنفس الطريقة.

## الخطوة 7: ربط اللعبة بـ Firebase

1. في Firebase: ⚙️ **Project settings** ← أسفل الصفحة **Your apps** ← اضغط أيقونة الويب **`</>`**.
2. اكتب أي اسم ← **Register app** (لا تفعّل Hosting).
3. ستظهر قيم `firebaseConfig`. انسخ القيم الخمس التالية.
4. في GitHub افتح `js/config.js` ← أيقونة القلم ✏️ ← عدّل الجزء الأخير:

```js
firebase: {
  apiKey: 'AIza...',
  authDomain: 'arabic-game-xxxx.firebaseapp.com',
  databaseURL: 'https://arabic-game-xxxx-default-rtdb.europe-west1.firebasedatabase.app',
  projectId: 'arabic-game-xxxx',
  appId: '1:123456:web:abcdef'
}
```

5. اضغط **Commit changes** وانتظر دقيقة حتى يتحدث الموقع.

> ⚠️ `databaseURL` ضروري. إن لم يظهر في الإعدادات، انسخه من أعلى صفحة **Realtime Database ← Data**.
>
> 🔐 قيم `firebaseConfig` ليست أسراراً، وظهورها في الموقع أمر طبيعي. الحماية الحقيقية تأتي من القواعد في الخطوتين 5 و6. لا تضع أبداً كلمة مرور أو «Service Account» في أي ملف.

## الخطوة 8: التجربة قبل الحصة

1. **المعلم:** افتح `https://USERNAME.github.io/arabic-game/teacher.html` ← سجّل الدخول ← «إنشاء الغرفة».
2. اضغط **▦ عرض QR**.
3. **الطالب:** امسح الرمز بكاميرا iPad (أو افتح الرابط على جهاز آخر) ← ابدأ المغامرة ← اختر شخصية ← اكتب الاسم ← ادخل الغرفة.
4. سيظهر الطالب في لوحة المعلم فوراً.
5. اضغط **▶ ابدأ اللعبة** ← عدّ تنازلي 3-2-1 عند الجميع في نفس اللحظة.
6. في النهاية اضغط **⏹ إنهاء اللعبة وإظهار النتائج**، وستظهر المنصة عند الجميع.

## 🎮 أثناء الحصة — لوحة المعلم

| الزر | ما يفعله |
|---|---|
| ▦ عرض QR | رمز كبير لعرضه على السبورة الذكية، مع رمز الغرفة المكوّن من 4 أرقام |
| 🔗 نسخ الرابط | لمشاركته عبر Teams أو Classroom |
| ▶ ابدأ اللعبة | يبدأ العد التنازلي عند جميع الطلاب في نفس اللحظة |

| ⏹ إنهاء اللعبة وإظهار النتائج | يوقف اللعب فوراً عند الجميع ويعرض الترتيب النهائي |
| 🏆 إظهار النتائج / 📊 لوحة الترتيب المباشرة | عرض كبير مناسب للشاشة |
| 🔁 جولة جديدة | نفس الطلاب، نتائج جديدة، وأسئلة مختلفة |

| ✕ بجانب الطالب | إخراجه من الغرفة (يستطيع الدخول مجدداً) |

**تحذير الأسماء المكررة:** إن كتب طالبان الاسم نفسه يظهر تنبيه أصفر. النظام يميّزهما داخلياً، لكن اطلب من أحدهما إضافة حرف أو اسم العائلة.

## 🏆 كيف يُحسب الترتيب؟

1. **عدد الإجابات الصحيحة** (الأعلى أولاً)
2. **عدد الأسئلة المُنجزة** — من أكمل يتقدّم على من لم يكمل عند التساوي
3. **الوقت الأقل**

مثال:

| الترتيب | الطالب | النتيجة | الوقت |
|---|---|---|---|
| 1 | محمد | 24/25 | 2:35 |
| 2 | أحمد | 24/25 | 2:41 |
| 3 | سالم | 23/25 | 2:20 |

- **الوقت:** يُحسب بتوقيت الخادم (لا يمكن التلاعب به بتغيير ساعة الجهاز)، من نهاية العد التنازلي حتى آخر إجابة، مع خصم فترات الإيقاف المؤقت.
- **الطالب المتأخر:** يُحسب وقته من لحظة دخوله.
- **النقاط ★:** للمتعة والتحفيز فقط (100 للإجابة الصحيحة + مكافأة سرعة حتى 50)، ولا تؤثر على الترتيب.

## ✏️ الدرس الحالي والأسئلة — `js/questions.js`

الدرس الحالي هو **الجملة والتركيب**، وكل ما يخصه موجود في ملف واحد هو `js/questions.js`: عنوان الدرس، ونصوص المراحل، والخيارات، والألوان، والأسئلة.

| المرحلة | السؤال | الخيارات |
|---|---|---|
| 1 🌴 | هل هذا جملة أم تركيب؟ | جملة / تركيب |
| 2 🏛️ | البوابتان | جملة / تركيب |
| 3 🔍 | ما نوع التركيب؟ | شبه جملة ظرفية / شبه جملة جار ومجرور / تركيب وصفي |
| 4 ⚡ | تحدي السرعة: نوع التركيب | نفس الخيارات الثلاثة، بترتيب ثابت |
| 5 🏰 | تعريف الجملة، تعريف التركيب، وأسئلة تفكير | خيارات خاصة بكل سؤال |

بعد كل إجابة تُلوَّن أجزاء التركيب ويظهر اسم كل جزء فوقه: ظرف ومضاف إليه، أو حرف جر واسم مجرور، أو موصوف وصفة.

**إضافة سؤال:** انسخ سطراً مشابهاً وعدّله:

```js
// المرحلتان 1 و2 (J = جملة ، T = تركيب)
{ text: 'البحرُ هادئٌ', answer: J, level: 1 },
{ text: 'البحرُ الهادئُ', answer: T, of: W, level: 1 },   // of = نوع التركيب لتلوين أجزائه

// المرحلتان 3 و4 (Z = ظرفية ، JM = جار ومجرور ، W = وصفي)
{ text: 'عندَ النافذةِ', answer: Z, level: 1 },

// المرحلة 5
{
  text: '', question: 'أيُّ ما يأتي جملة؟',
  options: ['الشجرةُ عاليةٌ', 'الشجرةُ العاليةُ', 'تحتَ الشجرةِ'],
  answer: 'الشجرةُ عاليةٌ',
  explain: 'تؤدي معنىً تامّاً.', level: 2
},
```

**قواعد مهمة:**

- لا تضع نقطة في آخر النص في المراحل 1–4؛ النقطة تكشف أن الكلام جملة.
- اجعل التركيب كلمتين فقط حتى يُلوَّن جزآه بشكل صحيح.
- يجب أن يبقى في كل مستوى أسئلة تكفي ما هو مطلوب في `pick` داخل `config.js`. البنك الحالي 77 سؤالاً، ويأخذ كل طالب 25 منها.
- انتبه للفواصل `,` وعلامات الاقتباس `'...'`. إن توقفت اللعبة بعد التعديل فغالباً هناك فاصلة ناقصة.
- لتغيير اسم نوع (مثلاً «شبه جملة ظرفية» إلى «شبه جملة ظرف») عدّل السطر `const Z = ...` في أعلى الملف فقط.

**الرجوع إلى درس «الاسمية والفعلية»:** الملف `js/questions-old-ismiya-filiya.js` هو الدرس السابق كما كان.

1. احذف `questions.js` أو غيّر اسمه.
2. غيّر اسم الملف القديم إلى `questions.js`.

ستعود اللعبة تلقائياً إلى الدرس السابق.

## ⚙️ تعديل الإعدادات — `js/config.js`

| الإعداد | المعنى |
|---|---|
| `gameTitle` | اسم اللعبة |
| `stages[].pick` | عدد الأسئلة من كل مستوى في كل مرحلة (حالياً 5 لكل مرحلة = 25) |
| `countdownSeconds` | مدة العد التنازلي |
| `maxGameMinutes` | مدة قصوى تنهي اللعبة تلقائياً (0 = بدون حد) |
| `allowLateJoin` | السماح بالدخول بعد بدء اللعبة |
| `maxNameLength` | أقصى طول للاسم |
| `scoring` | نقاط المتعة |
| `feedbackMs` | مدة عرض تصحيح الإجابة قبل السؤال التالي |
| `baseUrl` | اتركه فارغاً (يُكتشف تلقائياً) |

> إن غيّرت `scoring` بحيث يتجاوز `correct + speedBonusMax` الرقم 150، فعدّل الرقم `150` في قاعدة `points` داخل `database.rules.json` ثم أعد لصقها في Firebase.

## 💰 الخطة المجانية لـ Firebase (Spark)

تكفي لصف كامل بسهولة: حتى 100 اتصال متزامن و10 GB نقل بيانات شهرياً. اللعبة خفيفة جداً، إذ تستهلك الجولة الواحدة لـ 30 طالباً بضع مئات من الكيلوبايتات فقط.

للحفاظ على المساحة، استخدم «غرفة جديدة برمز جديد» التي تحذف الغرفة القديمة، أو احذف مجلد `sessions` القديم من تبويب Data من وقت لآخر.

## 🔐 الأمان — ماذا تحمي القواعد؟

**ما تحميه القواعد:**

- لا يستطيع أي طالب تعديل نتيجة طالب آخر، ولا تغيير حالة اللعبة (بدء، إيقاف، إنهاء).
- لا يستطيع أحد إنشاء غرف أو التحكم بها إلا حسابات المعلمين المسجّلة في `teachers`. ولا يتحكم المعلم إلا بغرفه.
- كل إجابة تُحفظ مرة واحدة فقط، فالضغط المزدوج لا يُحسب مرتين.
- لا يمكن زيادة النتيجة إلا سؤالاً واحداً في كل مرة، وأثناء اللعب فقط. بعد «إنهاء اللعبة» ترفض القاعدة أي إجابة جديدة.
- لا يرى الطلاب إجابات بعضهم.
- الوقت يُسجّل بتوقيت الخادم.

**حدود معروفة:**

تصحيح الإجابة يحدث على جهاز الطالب (لأن المشروع مجاني بلا خادم خاص). لذلك يستطيع طالب متمكّن تقنياً، يعرف أدوات المطوّرين، أن يسجّل إجاباته كلها صحيحة. هذا غير عملي على iPad في حصة مدتها دقائق، ومقبول للعبة تعليمية. الحل الكامل يتطلب Firebase Cloud Functions (خطة مدفوعة).

**اختياري:** لزيادة الحماية، قيّد مفتاح API من [Google Cloud Console](https://console.cloud.google.com/apis/credentials) ← المفتاح ← **Website restrictions** ← أضف `https://USERNAME.github.io/*`

## ♿ ملاحظات التصميم

- **واجهة عربية بالكامل** من اليمين لليسار، ومُحسّنة لـ Safari على iPad أفقياً وعمودياً، وتعمل على الهواتف.
- **رموز مع الألوان:** الأزرق ◆ = جملة، البرتقالي ▲ = تركيب، الأخضر المزرق ⏱ = شبه جملة ظرفية، البنفسجي ✦ = جار ومجرور، الوردي ✿ = تركيب وصفي. الرموز موجودة دائماً، فلا تعتمد المعلومة على اللون وحده.
- **تعليم مع التصحيح:** بعد كل إجابة تُلوَّن أجزاء التركيب ويظهر اسم كل جزء (ظرف / مضاف إليه، حرف جر / اسم مجرور، موصوف / صفة)، ويُوسم الكلام التام بـ«معنى تام ✓».
- **ثبات موضع الخيارات:** «جملة» و«تركيب» في مكانهما دائماً، وكذلك أنواع التركيب في تحدي السرعة، لأن الثبات يساعد الطالب. ويُضمن التوازن باختيار عدد متقارب من كل نوع لكل طالب. أما خيارات المرحلتين 3 و5 فتُخلط عشوائياً.
- **تقليل الحركة:** يحترم إعداد «تقليل الحركة» في الجهاز.
